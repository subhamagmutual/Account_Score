# Physician MPL Account Scoring Model

A parameter-driven scoring pipeline for Medical Professional Liability (Malpractice) insurance. Produces a composite risk score (1-10) for each physician-year record based on four dimensions: Adequacy, Capacity, Appetite, and Environment.

## Project Structure

```
Account_Score/
├── config/
│   ├── pipeline_params.json        # Data paths, filters, credibility, binning methods
│   ├── scoring_weights.json        # Component and sub-score weights
│   ├── specialty_tiers.json        # Specialty → risk score mapping (1-10)
│   ├── state_tiers.json            # State → risk score mapping (1-10)
│   └── binning_thresholds.json     # Auto-generated bin boundaries (created by fit step)
├── src/
│   ├── __init__.py
│   ├── utils.py                    # Shared utilities (safe_divide, weighted_average, rescale)
│   ├── config_loader.py            # Loads and validates JSON configs
│   ├── data_loader.py              # Loads CSV, selects needed columns, applies filters
│   ├── kpi_calculator.py           # Computes derived KPIs (loss cost, frequency, severity)
│   ├── binner.py                   # BinFitter (auto-compute thresholds) + BinApplier (apply)
│   ├── credibility.py              # Z-factor credibility weighting
│   ├── scorer.py                   # Computes component and composite scores
│   ├── output_builder.py           # Builds output DataFrame, exports CSV/Excel
│   └── pipeline.py                 # Main orchestrator (batch + single-record)
├── run_pipeline.py                 # CLI entry point
├── create_presentation.py          # Generates PowerPoint summary with charts
└── requirements.txt                # Python dependencies
```

## Configuration

All model parameters live in JSON files under `config/`. No code changes are needed to adjust weights, thresholds, or tier mappings.

| File | Purpose |
|------|---------|
| `pipeline_params.json` | Input/output paths, data filters, credibility settings, binning methods |
| `scoring_weights.json` | Composite dimension weights (40/25/25/10) and all sub-score definitions |
| `specialty_tiers.json` | Maps 25 specialties to risk scores 1-10 |
| `state_tiers.json` | Maps 38 states to risk scores 1-10 |
| `binning_thresholds.json` | Generated by the fit step; can be manually adjusted afterward |

## Running the Pipeline

### Basic Usage

```bash
# Full pipeline: fit binning thresholds from data + score all records
python run_pipeline.py

# Quick test with a sample of records
python run_pipeline.py --sample 10000

# Fit binning thresholds only (no scoring output)
python run_pipeline.py --mode fit_only

# Score using previously fitted thresholds (no re-fitting)
python run_pipeline.py --mode score_only
```

### Command-Line Arguments

| Argument | Default | Description |
|----------|---------|-------------|
| `--mode` | `fit_and_score` | Pipeline mode: `fit_and_score`, `fit_only`, or `score_only` |
| `--config` | `./config` | Path to configuration directory |
| `--input` | (from config) | Override input CSV file path |
| `--output` | (from config) | Override output directory |
| `--sample` | None (full data) | Number of records to sample for testing |

### Examples

```bash
# Score with a different input file
python run_pipeline.py --input "C:/path/to/my_data.csv"

# Direct output to a specific folder
python run_pipeline.py --output "C:/Box/Box/BOX Subhashree Singh/Business/PAS"

# Fit on 5000 records, useful for iterating on threshold adjustments
python run_pipeline.py --mode fit_only --sample 5000

# Score full dataset using existing binning_thresholds.json
python run_pipeline.py --mode score_only
```

## Typical Workflow

1. **Fit and explore** (with sample):
   ```bash
   python run_pipeline.py --sample 10000
   ```
   This generates `binning_thresholds.json` and scored output files.

2. **Review thresholds**: Open `config/binning_thresholds.json` and adjust bin boundaries based on actuarial judgment.

3. **Score with adjusted thresholds**:
   ```bash
   python run_pipeline.py --mode score_only
   ```

4. **Generate presentation**:
   ```bash
   python create_presentation.py
   ```
   Reads the most recent scoring output and produces a 12-slide PowerPoint.

## Output Files

The pipeline writes to the output directory specified in `pipeline_params.json` (or via `--output`):

- `physician_scores_YYYYMMDD_HHMMSS.csv` - Flat file with all scores
- `physician_scores_YYYYMMDD_HHMMSS.xlsx` - Multi-sheet Excel workbook:
  - **Scores** - Full physician-level results
  - **Score_Distribution** - Composite score frequency table
  - **Component_Stats** - Summary statistics per component
  - **By_Specialty** - Average scores by specialty
  - **By_State** - Average scores by state

### Output Columns

| Category | Columns |

## Scoring Methodology

### Scale
- **Sub-scores**: 1 to 30 (internal granularity)
- **Component scores**: 1 to 10 (rescaled from sub-scores)
- **Composite score**: 1 to 10 (weighted average of components, capped)
- **Interpretation**: 1 = Best risk, 10 = Worst risk

### Composite Formula

```
Composite = 0.40 * Adequacy + 0.25 * Capacity + 0.25 * Appetite + 0.10 * Environment
```

### Credibility Weighting

Loss-based sub-scores (adequacy dimension) are blended with the portfolio average using:

```
Z = min(sqrt(Written_Premium / $50,000), 1)
Blended_Score = Z * Individual_Score + (1 - Z) * Portfolio_Average
```

This prevents thin accounts (low premium) from receiving extreme scores.

### Missing Value Handling

When a sub-score cannot be computed (missing data), its weight is set to zero and it is excluded from the weighted average. No penalty is applied for missing data.

## Notes

- The input CSV is ~3.8 GB with 1700+ columns. The pipeline reads only the ~30 needed columns via `usecols` for efficiency.
- When using `--sample`, the pipeline reads `sample_n * 5` rows from the CSV, applies filters, then randomly samples to the requested count.
- For full-dataset runs without `--sample`, ensure sufficient time and memory (the read alone can take 10+ minutes).
- All configurations use forward slashes in paths (works on both Windows and Linux with pandas).
